## 1. 基本方針

1. **月次で計算し、年次で集計・表示する**（【要決定 Q-01】推奨案）。
   - 理由: 住宅ローン返済・賞与月・子の進学（4月）・誕生月による年齢到達など、月単位の事象が多い。1,200 か月程度の計算量は問題にならない。
   - 年次表示では「その年（暦年、【要決定 Q-02】）の月次フローの合計」と「年末時点の残高」を表示する。
2. **すべての金銭移動を「口座間の移動（仕訳）」として記録する**。残高は仕訳の積み上げでのみ変化させる。これにより二重計上・計上漏れを構造的に防ぐ（§5）。
3. **入力データ（シナリオ）と導出データ（計算結果）を分ける**。イベントが生成する収支・口座は保存せず、毎回の計算時に展開する（§6）。
4. 計算エンジンは**純粋関数**: `simulate(scenario) → SimulationResult`。現在時刻・乱数・グローバル状態に依存しない。

## 2. 時間の扱い

### 2.1 年月の表現

- 年月は整数の**通し月番号** `monthIndex = year * 12 + (month - 1)` で内部表現する（タイムゾーン・日付ずれを排除）。
- 日（day）は扱わない。すべての事象は「その月」に発生する。
- 表示・入力は `YYYY-MM` 形式。

### 2.2 シミュレーション期間

- 開始: シナリオの `startYearMonth`（既定: 作成時の翌月。保存されるのは値であり、後から自動で変わらない）
- 終了: 本人が `endAge` 歳に到達する年月の月末（既定 100 歳、範囲 60〜110）
- 開始時点の口座残高は「開始月の期首残高」とする。

### 2.3 年齢

- 世帯メンバーは生年月 `birthYearMonth` を持つ。
- 月 m における満年齢: `age(m) = floor((m - birthMonthIndex) / 12)`。誕生月に1歳加算される。
- 年次表では、各年の**年末（12月）時点**の満年齢を表示する（【要決定 Q-02】年度表示を選ぶ場合は3月時点）。

### 2.4 年齢指定のトリガー

イベントや収支項目の開始・終了は次のいずれかで指定できる。

| 指定方法 | 解決規則 |
|---|---|
| 年月指定 `{type:'date', yearMonth}` | その月 |
| 年齢指定 `{type:'age', memberId, age, month?}` | 指定メンバーが `age` 歳になる誕生月。`month` 指定時は「`age` 歳である期間中の指定月」(例: 65歳の年度末=3月) |
| 学年指定 `{type:'school', childId, grade}` | 日本の学齢規則による4月（§2.5） |
| 相対指定 `{type:'relative', eventId, offsetMonths}` | 他イベントの発生月 ± n か月（P2） |

- 解決後の月がシミュレーション期間外の場合、期間外部分は無視する（エラーにはしないが、UI で注意表示）。

### 2.5 学齢（日本の就学規則）

- 4月2日〜翌年4月1日生まれが同一学年。日を持たないため、**4月生まれは「4月2日以降生まれ」とみなす**（【要決定 Q-03】誕生日を持つかどうか）。
- 小学校入学年: 生年月の月が 4〜12 月なら `生年 + 7`、1〜3 月なら `生年 + 6` の 4 月。
- 以降、中学 +6 年、高校 +9 年、大学 +12 年（いずれも 4 月）。

### 2.6 期間の端点

- 収支項目の期間 `[start, end]` は**両端を含む**（開始月にも終了月にも計上）。
- `end` 未指定はシミュレーション終了まで。
- 「X 歳まで」と指定した場合、**X 歳の誕生月の前月まで**（= X 歳になったら停止）とするか、**X 歳の最終月まで**とするかで1年ずれる。推奨: UI 文言で「X 歳になる月の前月まで（X 歳未満の間）」と「X 歳の間も含む」を明示選択させる。既定は前者（【要決定 Q-04】）。

## 3. 金額と精度

| 項目 | 規則 |
|---|---|
| 内部単位 | 円 |
| 型 | JavaScript `number`。仕訳金額は常に**整数円**（`Number.isSafeInteger` を満たす。上限 約 9,007 兆円で十分） |
| 率 | 年率を小数で保持（例: 1.5% → `0.015`）。率そのものは丸めない |
| 丸め時点 | **仕訳を作る瞬間に1回だけ**丸める。残高は整数仕訳の合計なので丸め誤差が累積・伝播しない |
| 浮動小数の正規化 | 丸め・切り捨ての直前に**有効数字 15 桁へ正規化**してから丸める（例: `100 × 1.005` は倍精度で `100.49999999999999` になるが、正規化して `100.5` → 101 円）。倍精度の表現誤差（約 16 桁目）だけを除去するためで、独立参照実装（Decimal 40 桁）と結果を一致させる。2026-10-26 追加 |
| 丸め方法 | 既定: 四捨五入（`Math.round` ではなく、負数も対称な「0から遠い方向への四捨五入」）。ローン利息のみ切り捨て（金融機関の一般的慣行に合わせる）【要決定 Q-05】 |
| 成長率の適用 | 金額 × (1+率)^経過年数 を浮動小数で計算 → 仕訳作成時に丸め。前年の丸め後金額に率を掛けない（誤差累積の回避） |
| 表示 | 円単位または万円単位（小数1位）。表示時の丸めは計算に影響させない |

> decimal.js 等の任意精度ライブラリは初期版では使わない。整数円仕訳 + 1回丸めで十分な精度が得られ、テストで恒等式を厳密（誤差 0 円）に検証できるため。

## 4. 口座モデル

### 4.1 口座種別

| 種別 `kind` | 分類 | 例 | 残高の変動要因 |
|---|---|---|---|
| `cash` | 流動資産 | 普通預金・財布（世帯の生活口座） | すべての収入・支出の入出金先 |
| `savings` | 流動資産 | 定期預金 | 振替、利息 |
| `investment` | 金融資産 | 投資信託・株式・NISA 等 | 振替（積立/取崩）、運用損益 |
| `property` | 実物資産 | 自宅不動産 | 購入、評価額変動（減価） |
| `vehicle` | 実物資産 | 自動車 | 購入、減価、売却 |
| `other_asset` | その他資産 | 貸付金等 | 任意 |
| `loan` | 負債 | 住宅ローン、自動車ローン、奨学金 | 借入（増加）、元本返済（減少） |

- 負債は**正の数で残高を保持**し、純資産計算で減算する。
- 各シナリオに `cash` 口座は**ちょうど1つ**存在し、これを「メイン口座」とする（初期版の簡略化。複数の現金口座は P2）。
- 純資産 = Σ資産口座残高 − Σ負債口座残高
- 金融資産 = cash + savings + investment（実物資産を除いた指標。資金計画上はこちらを重視）

### 4.2 外部（世帯の外）

収入・支出は「外部」との取引。外部は残高を持たない仮想口座 `EXTERNAL` として扱う。

## 5. 仕訳（ポスティング）モデル — 二重計上・計上漏れの防止

### 5.1 仕訳の構造

```ts
type Posting = {
  month: MonthIndex;
  from: AccountId | 'EXTERNAL';
  to: AccountId | 'EXTERNAL';
  amount: number;          // 正の整数円
  type: PostingType;       // 下表
  category: string;        // 表示用カテゴリ（給与、住居費、教育費…）
  sourceId: string;        // 生成元（収支項目ID / イベントID / 口座ID）
  sourceKind: 'item' | 'event' | 'account' | 'system';
};
```

| `type` | from → to | 収支表上の扱い |
|---|---|---|
| `income` | EXTERNAL → cash | 収入 |
| `expense` | cash → EXTERNAL | 支出 |
| `transfer` | 資産 → 資産 | **収入にも支出にも含めない**（積立・取崩・定期預金への預入） |
| `asset_purchase` | cash → 実物資産 | 収支表では「資産購入」として別掲（支出合計には含めない設定が既定。【要決定 Q-08】） |
| `loan_draw` | loan → 資産（借入で実物資産を取得） | 収支表に含めない（負債と資産が同額増える） |
| `loan_principal` | cash → loan | 「ローン元本返済」として別掲。純資産は変化しない |
| `loan_interest` | cash → EXTERNAL | 支出（利息） |
| `investment_return` | EXTERNAL ↔ investment | 運用損益（収入でも支出でもない別枠） |
| `interest` | EXTERNAL → savings/cash | 利息収入（運用損益枠） |
| `revaluation` | EXTERNAL ↔ 実物資産 | 評価損益（減価） |

### 5.2 不変条件（テストで全月検証する）

1. **残高恒等式**: すべての口座・すべての月で `期末残高 = 期首残高 + Σ流入仕訳 − Σ流出仕訳`。残高は仕訳からのみ計算し、直接書き換えない。
2. **純資産恒等式**: `Δ純資産 = 収入 − 支出(利息含む) + 運用損益 + 評価損益`。振替・ローン元本返済・借入・資産購入は純資産を変えない。
3. **一意生成**: 同一 `(sourceId, month, type, 子キー)` の仕訳は高々1件。重複があればエンジンが例外を投げる（イベント二重適用の検出）。
4. **網羅性**: 期間内で有効な全収支項目について、該当月に仕訳が存在する（金額0でない限り）。テストで「期待される発生回数」と照合。
5. 仕訳金額はすべて正の整数（向きは from/to で表す）。運用損失は `investment → EXTERNAL` として表す。

### 5.3 二重計上が起きやすい箇所と対策

| リスク | 対策 |
|---|---|
| 積立額を「支出」と「投資残高増加」の両方で数える | 積立は `transfer`。支出合計に入れない |
| 住宅購入時、購入額を支出計上し、さらに不動産資産として計上 | 購入は `asset_purchase`/`loan_draw`。支出ではない。諸費用（登記・仲介手数料等）のみ `expense` |
| ローン返済額全額を支出計上し、ローン残高も減らす | 返済を「利息（支出）」と「元本（負債減少）」に分割 |
| 家賃が住宅購入後も残る | 住宅購入イベントが「終了させる収支項目」を明示参照（`endsItemIds`）。終了指定がない賃貸住居が購入後も重なる場合は検証警告 |
| 同じイベントを2回入力・複製時の ID 重複 | ID は UUID。シナリオ複製時は全 ID を振り直し、参照も変換。検証で重複検出 |
| 年金額を手取り入力済みなのに再度税控除 | 収入項目に `amountBasis: 'net' | 'gross'` を持たせ、初期版は `net` のみ受け付ける |
| 退職金を給与収入と重複入力 | 退職イベントが生成する一時収入は `sourceKind: 'event'` で区別。年次明細で出所を表示 |

## 6. 計算パイプライン

```
Scenario（保存データ）
  │ 1. 検証（スキーマ・参照整合性）            → ValidationIssue[]
  │ 2. トリガー解決（年齢/学年 → 月番号）
  │ 3. イベント展開（Event → 派生収支項目・派生口座・一時仕訳ルール）
  │ 4. 収支ルール集合の確定（基本項目 + 派生項目、終了指定の適用）
  │ 5. 月次ループ（§7）                       → Posting[]、口座残高
  │ 6. 集計（月次行 → 年次行、指標算出）
  ▼
SimulationResult（保存しない。毎回再計算）
```

- イベント展開は**決定的な順序**で行う（イベント発生月昇順 → 同月はイベント種別の定義順 → ID 昇順）。
- 派生要素の ID は `${eventId}:${role}` の形で決定的に付与し、二重展開を検出可能にする。

## 7. 月次ループ内の処理順序

各月 m について、以下の順に処理する（順序は結果に影響するため固定する）。

1. **期首残高**の確定（前月末残高）。
2. **運用損益・利息**: 期首残高に月次利回りを適用（`investment`, `savings`, 利回り設定のある `cash`）。
   - 月次利回り `r_m = (1 + r_annual)^(1/12) − 1`（幾何換算。【要決定 Q-07】）。
   - 当月中の入出金には当月の利回りを適用しない（＝月末入出金とみなす）。
3. **実物資産の評価変動**（§10）。
4. **収入**: 有効な収入ルールの当月額を `income` 仕訳。
5. **一時収支・資産購入・借入**（イベント由来）。
6. **定常支出**: 有効な支出ルールの当月額を `expense` 仕訳。
7. **ローン返済**: 各ローンの利息・元本を計算し仕訳（§9）。
8. **振替（積立・取崩ルール）**: 設定された積立・取崩を `transfer` 仕訳。
9. **資金不足処理**（§11）。
10. **期末残高**の確定と月次行の記録。

## 8. 収入・支出

### 8.1 収支項目（定常）

```ts
type FlowItem = {
  id: string;
  direction: 'income' | 'expense';
  name: string;
  category: Category;            // 給与/賞与/事業/年金/その他収入, 食費/住居/教育/保険/車両/…
  ownerId?: MemberId;            // 収入の稼ぎ手、支出の対象者（任意）
  amount: number;                // 円（開始時点の価格）
  frequency: 'monthly' | 'yearly' | 'months'; // yearly は1回/年、months は指定月（賞与: [6,12]）
  months?: number[];             // frequency が yearly/months の場合の発生月（1-12）
  start: Trigger; end?: Trigger;
  growth: { type: 'none' } | { type: 'inflation' } | { type: 'fixed', rate: number };
  growthStepMonth?: number;      // 上昇の適用月（既定: 給与=4月、それ以外=1月）【要決定 Q-10】
  amountBasis: 'net';            // 初期版は手取り（Q-06）
};
```

- **一時収支**は `OneTimeFlow { id, direction, amount, month(trigger), category }`。成長率は `growth` を指定した場合のみ開始時点からの経過年数で適用（例: 将来の車購入価格を物価連動させる）。

### 8.2 上昇率（昇給率・物価上昇率）

- 経過年数 `n` = 項目の基準時点（既定: シミュレーション開始年月）から当月までに通過した `growthStepMonth` の回数。
- 当月額 = `round(amount × (1 + rate)^n)`。
- `growth: inflation` はシナリオの物価上昇率 `assumptions.inflationRate` を使う。
- 物価上昇率は初期版では**全期間一定**。期間別の率は P2。
- 昇給の上限（例: 55 歳で頭打ち）は、P1 では「収支変更イベント」で表現する。年齢別昇給カーブは P2。

### 8.3 年金

- 初期版は利用者が「受給開始年齢」と「年額（手取り見込み、現在価値）」を入力する。
- 物価・賃金スライド、マクロ経済スライドは近似として「物価上昇率 − 調整率」を任意入力（既定: 物価連動なし = 名目一定）【要決定 Q-11】。
- 繰上げ・繰下げ受給の増減率は P2（受給開始年齢に応じて 1 か月あたり −0.4% / +0.7% を自動計算）。

## 9. ローン計算

### 9.1 入力

`Loan { principal, annualRate, termMonths, method: 'equal_payment' | 'equal_principal', startMonth, rateSchedule?: {fromMonth, annualRate}[] }`

### 9.2 元利均等返済（equal_payment）

- 月利 `r = annualRate / 12`（日本の住宅ローン慣行の単純月割り）。
- 毎月返済額 `P = L × r / (1 − (1 + r)^(−n))`、`r = 0` の場合 `P = L / n`。
- `P` は**円未満切り捨て**（【要決定 Q-05】）。
- 各月: 利息 `I = floor(残高 × r)`、元本 `= P − I`。
- **最終回**は残高全額を元本とし、返済額 = 残高 + 利息（端数調整）。最終回後の残高は必ず 0。
- 変動金利（`rateSchedule`）: 金利変更月に残高・残期間から `P` を再計算する（5年ルール・125%ルールは P2）。

### 9.3 元金均等返済（equal_principal）

- 毎月元本 = `floor(L / n)`、最終回で端数調整。利息 = `floor(残高 × r)`。

### 9.4 借入時の仕訳

- 住宅購入: `loan_draw`（loan → property）で借入額分、`asset_purchase`（cash → property）で頭金分。諸費用は `expense`。
- 不動産の取得価額 = 頭金 + 借入額（物件価格）。

### 9.5 繰上返済（P2）

期間短縮型 / 返済額軽減型。

### 9.6 住宅ローン控除

初期版は扱わない（P2: 年末残高 × 控除率を上限付きで収入計上する簡易版）。

## 10. 実物資産の評価

- 不動産: 既定は「建物部分を耐用年数で定額減価、土地は一定」の簡易モデル、または「評価額を年率 x% で変動」の2方式から選択（【要決定 Q-12】推奨: 年率変動のみの単純方式を P1、建物/土地分離は P2）。
- 車両: 年率で減価（既定 −15%/年）。買い替え時は残存価値で売却（`transfer` 相当: vehicle → cash）。
- 実物資産は**金融資産には含めない**。グラフでは区別して表示する。

## 11. 資金不足（負の現金残高）の扱い

推奨案（【要決定 Q-13】）:

1. **既定: マイナスを許容して計算を継続**し、`cash` 残高 < 0 の月を「資金不足」として記録する。マイナス残高に利息は付けない。
2. 結果に以下を出力: 初回不足年月・年齢、最大不足額、不足月数。
3. オプション（P1 で実装可能だが既定 OFF）: **自動取り崩し** — cash がマイナスになった月に、指定順（savings → investment）で不足額を振替補填する。補填しきれない分はマイナスのまま。
4. 投資・実物資産の残高はマイナスにしない（取崩ルールは残高を上限とする）。

## 12. 税金・社会保険・年金の計算範囲

| 項目 | 初期版（v1.0） | 将来版 |
|---|---|---|
| 所得税・住民税 | 計算しない。収入は**手取り額**で入力 | 額面から給与所得控除・基礎控除・扶養控除等を経て算出（P2: 簡易版、P3: 詳細） |
| 社会保険料 | 計算しない（手取りに含めて入力） | 標準報酬月額ベースの概算（P2） |
| 賞与 | 手取りで入力 | 同上 |
| 退職金課税 | 手取りで入力 | 退職所得控除（P2） |
| 年金 | 見込み額（手取り）を入力 | 加入期間・平均標準報酬からの概算（P3）、繰上/繰下（P2） |
| 年金・高齢期の税/社保 | 手取り入力 | 公的年金等控除・介護保険料（P3） |
| 運用益課税 | 税引後の期待利回りを入力 | 課税口座/非課税口座の区別、取崩時課税（P2） |
| 住宅ローン控除 | なし | 簡易版（P2） |
| 児童手当 | 収入項目として手動入力（テンプレートで入力補助） | 制度に基づく自動算出（P2） |
| 固定資産税 | 住宅購入イベントで年額を入力 | 評価額連動（P3） |

制度値（税率表・控除額）を将来導入する際は、**年度付きの制度パラメータファイル**として計算エンジンから分離し、計算結果に使用した制度年度を表示する。

## 13. 出力

```ts
type SimulationResult = {
  scenarioId: string;
  engineVersion: string;            // 計算仕様のバージョン
  monthly: MonthlyRow[];            // 月次
  yearly: YearlyRow[];              // 年次（暦年）
  postings: Posting[];              // 明細（年次ドリルダウン用）
  events: ResolvedEvent[];          // 解決済み発生月
  metrics: {
    netWorthAt: Record<number, number>;   // 年齢 → 純資産
    minCash: { amount: number; month: MonthIndex };
    shortfall: { firstMonth?: MonthIndex; maxAmount: number; months: number };
    lifetimeIncome: number; lifetimeExpense: number;
  };
  issues: ValidationIssue[];        // 警告（期間外イベント、重なり等）
};

type YearlyRow = {
  year: number; ages: Record<MemberId, number>;
  income: number; expense: number; netCashFlow: number;   // 収入 − 支出（振替・元本返済除く）
  loanPrincipal: number; assetPurchase: number;
  investmentReturn: number; revaluation: number;
  balances: Record<AccountId, number>;   // 年末残高
  financialAssets: number; realAssets: number; liabilities: number; netWorth: number;
  byCategory: Record<string, number>;
};
```

- 「現金収支」= 収入 − 支出 − ローン元本返済 − 資産購入（頭金） ± 振替。年次表で「収支（損益ベース）」と「現金の増減」を区別して表示する。

## 14. 入力バリデーション（エンジン側）

| 区分 | 規則 | 種別 |
|---|---|---|
| 金額 | 0 以上の整数、上限 1,000 億円 | エラー |
| 率 | −50% 〜 +50%（年率） | エラー。±15% 超は警告 |
| 期間 | `start ≤ end` | エラー |
| 生年月 | 1900-01 以降。本人・配偶者は開始年月以前（子は出産予定として将来の年月も可） | エラー |
| 参照 | イベント/項目が参照するメンバー・口座・項目が存在する | エラー |

## 16. 実装で確定した細部（Phase 2, 2026-10-26）

| 項目 | 確定内容 |
|---|---|
| 計算終了月 | 本人が `endAge` 歳になる誕生月を含む（例: 1990-01 生まれ・終了 65 歳 → 2055-01 まで） |
| 振替の上限 | 生活口座**以外**からの振替（取崩）は振替元の残高を上限とする。生活口座からの積立は上限を設けない（生活口座がマイナスになれば資金不足として表示し、原因を明細で確認できる） |
| その他資産 | `other_asset` の年率は評価額の変動率として扱い、評価損益に計上する |
| 利息の対象 | `cash`・`savings` の利息、`investment` の運用損益は、期首残高が正の場合のみ計上する |
| 年次の説明 | 各年について「期首純資産 + 収入 − 支出 + 運用損益 + 評価損益 = 期末純資産」と「期首の生活口座 + 入出金の内訳 = 期末の生活口座」を出力する（`explainYear`）。照合差は常に 0 であることをテストで確認 |
| 参照切れ | 存在しない（または無効化したイベントで追加される）メンバーを参照する収支・イベントは警告を出して計算から除外する（エラーにはしない） |
| 浮動小数 | §3 の「浮動小数の正規化」を参照 |

## 17. 人生イベントの展開（Phase 3, 2026-10-26）

共通規則:
- イベントの発生月 = `trigger` を開始として解決した月。無効（`enabled: false`）のイベントは一切計算に含めない
- 生成物の ID はイベント ID を接頭辞とする決定的な ID（例: `${eventId}:loan`）。保存データには書き戻さず、計算のたびに作り直す（再計算で二重適用されない。仕訳の一意キーでも検出）
- 一時金は発生月に、継続的な収支は「収支ルール」として発生月から計上する。一時支出と継続的な収支変化を区別する
- 「入力した金額の時点」は既定で**シミュレーション開始時点の価格**。物価連動を選んだ一時金は開始時点から発生月までの上昇（毎年 1 月適用）を反映する
- `endsIds` に指定した収支項目（またはイベント）は、発生月の**前月**で終了する。イベントを指定した場合、そのイベントの定期的な一時金（賃貸の更新料）も発生月以降は計上しない（2026-10-26 追加: テストで更新料が残る不具合を検出したため明記）
- 結婚イベントは配偶者（`${eventId}:spouse`）、出産イベントは子（`${eventId}:child`、生年月 = 発生月）を世帯に追加する。他の項目・イベントはこの ID を対象者として参照できる。追加元のイベントが無効な場合、参照する項目は警告を出して計算から除外する

| 種別 | 一時金（発生月） | 継続的な収支・口座 |
|---|---|---|
| `one_time` 一時収支（旅行・大型支出・臨時収入） | 収入または支出 | なし |
| `flow_change` 収支の変更（昇給・老後の生活費変更など） | なし | 収支テンプレート（発生月開始） |
| `job` 就職・転職・独立 | 費用（支出: 開業費・転職費用） | 収支テンプレート（新しい給与・事業収入） |
| `retirement` 退職 | 退職金（収入・手取り） | 収支テンプレート（再雇用など）。給与の終了は `endsIds` で指定 |
| `marriage` 結婚 | 費用（支出） | 配偶者の追加、収支テンプレート（配偶者の収入・生活費の変化） |
| `birth` 出産 | 出産費用（支出・給付金差引後） | 子の追加、収支テンプレート（子育て費・児童手当など） |
| `education` 教育費 | 大学入学費用（大学入学月に支出） | 段階ごとの年額 ÷ 12 を、入学月（4 月）から段階の年数分（幼 3・小 6・中 3・高 3・大 4 年）毎月計上 |
| `rent` 賃貸・引っ越し | 入居時費用（支出） | 家賃（毎月、終了指定まで）、更新料（入居月から N 年ごと、家賃と同じ上昇率） |
| `home_purchase` 住宅購入 | 頭金（資産購入）、借入（負債と不動産が同額増加）、諸費用（支出） | 住宅ローン返済（翌月から）、管理費・修繕積立金（毎月）、固定資産税等（購入翌年から毎年 4 月）、不動産の評価変動 |
| `car` 自動車 | 購入（資産購入、ローン時は頭金 + 借入）。買い替え時は前の車両を評価額で売却してから購入 | 自動車ローン返済（翌月から）、維持費（年額 ÷ 12 を毎月）、車両の評価変動、手放す月に売却 |
| `pension` 年金受給 | なし | 年額 ÷ 12 を毎月（伸び率は毎年 4 月に適用、既定 0 = 名目一定） |

### 住宅ローン・自動車ローンの扱い（明示）

| 項目 | 扱い |
|---|---|
| 借入額 | 物件（車両）価格 − 頭金。頭金が価格を超える場合は警告して計算に含めない |
| 金利 | 年率を入力。月利 = 年率 ÷ 12。`rateChanges`（初回返済から N か月後に金利 X%）で変動金利を簡易表現し、変更月に残高と残り回数から返済額を再計算 |
| 期間 | 返済回数（月）。1〜600 |
| 返済方式 | 元利均等 / 元金均等 |
| 返済頻度 | 毎月のみ。ボーナス払いは未対応 |
| 返済開始 | 借入月の翌月 |
| 手数料 | 融資手数料・保証料・登記費用などは「諸費用」として購入月に支出計上する（ローン残高には含めない） |
| 仕訳 | 頭金 = 生活口座 → 不動産（資産購入）、借入 = ローン → 不動産、返済 = 利息（支出）＋ 元本（生活口座 → ローン、負債の減少）。元本返済は生活費（支出）に含めず、資産を二重に減らさない |
| 住宅ローン控除・繰上返済・団信 | 未対応 |
