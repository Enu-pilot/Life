## 2. 各 Phase の作業と完了条件

### Phase 1: アプリ基盤とデータ管理
**完了条件**
- [x] 主要な入力（プロフィール・前提条件・収入・支出・資産・積立）ができ、検証エラーが表示される
- [x] IndexedDB への自動保存・再読み込みで値が保持される（単体・UI・E2E テスト）
- [x] 保存失敗時に「保存済み」と表示しない
- [x] 欠損・破損・不正な保存データを検出し、データを消さずに復旧手段を示す
- [x] スキーマバージョンと逐次マイグレーションの枠組みがあり、テストされている
- [x] lint 相当（型検査 + 層分離テスト）、単体テスト、E2E が成功

### Phase 2: 計算エンジン
**完了条件**
- [ ] 計算が UI に依存せず実行できる（層分離テスト）
- [ ] 必須検証（収支なし／収入>支出／支出>収入／初期資産ゼロ／途中変更／長期間／月末・年末境界／丸め・浮動小数／決定性）がすべて成功
- [ ] 期待値を独立計算（手計算・Python 独立実装）で求めている
- [ ] 全月で残高恒等式・純資産恒等式が誤差 0 円で成立（プロパティテスト含む）
- [ ] 年次ごとに「期首 + 収入 − 支出 + 運用損益 + 評価損益 = 期末」を説明する出力がある
- [ ] 未実装項目（税・社保・運用益課税）を実装済みとして扱っていない

### Phase 3: 人生イベント
**完了条件**
- [ ] P1 イベント（就職・転職・独立・退職、結婚・出産・子育て・教育費、賃貸・引っ越し・住宅購入、住宅ローン、自動車、一時支出、年金）の追加・編集・削除・無効化が結果に反映される
- [ ] イベント単体・組み合わせのテスト、再計算で二重適用しないことのテスト
- [ ] 住宅ローンの借入額・金利・期間・返済方式・返済頻度・手数料の扱いを明示し、元本返済と生活費を区別
- [ ] イベント適用前後の差分を確認できる

### Phase 4: グラフ・シナリオ比較
**完了条件**
- [ ] 複数シナリオの作成・複製・編集・切替・比較が動作し、相互に影響しない
- [ ] グラフと数値表の値が一致（同一データ由来であることをテスト）
- [ ] 比較結果に前提条件と計算期間を表示。データ不足時は理由を示し確定的に表示しない
- [ ] 資金不足の発生時期と原因（その年の明細）を確認できる

### Phase 5: 高度な計算モデル
**完了条件**
- [ ] 追加したモデルごとに計算仕様・根拠（一次情報）・対象条件・テストがある
- [ ] 制度値は設定（パラメータ）として管理し、施行時期・出典を記録
- [ ] 実際の制度計算と簡易推計を区別して表示
- [ ] 回帰テストが成功し、未対応の計算を明示

### Phase 6: データ保護・総合テスト・リリース準備
**完了条件**
- [ ] JSON 完全バックアップ・復元、CSV 出力、不正ファイルの安全な拒否、失敗時のデータ保護
- [ ] 主要画面の表示・入力エラー確認（E2E）
- [ ] 大量イベント・長期シミュレーションの性能測定
- [ ] 全自動テスト成功、既知の問題・未対応機能・起動方法を文書化

## 3. Phase 完了時の報告フォーマット

1. 変更ファイル一覧
2. 実装内容（実装済み / 未実装を明確に区別）
3. 実行したテストのコマンドと結果（件数・成功/失敗）。実行していないテストは「未実行」と明記
4. 完了条件のチェック結果（未達項目があれば Phase を完了扱いにしない）
5. 既知の問題
6. 決定した仕様・新たに発生した未決事項
7. 次 Phase へ進むための条件
