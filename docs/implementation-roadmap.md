## 1. 全体像

| Phase | 名称 | 主な成果 | 対象リリース |
|---|---|---|---|
| 0 | 調査・要件定義・計画 | docs/ 一式 | — |
| 1 | 基盤と計算エンジン中核 | プロジェクト雛形、ドメイン型、時間・仕訳・収支・運用・ローン計算、検証、集計 | v1.0 |
| 2 | 人生イベント展開 | P1 イベント種別の展開器、資金不足処理、ゴールデンテスト | v1.0 |
| 3 | 永続化とデータ管理 | IndexedDB 保存、エクスポート/インポート、マイグレーション基盤 | v1.0 |
| 4 | UI（入力・結果表示） | 全画面（ダッシュボード・入力・イベント・推移グラフ/表・設定） | v1.0 |
| 5 | シナリオ比較 | シナリオ管理・複製・比較画面 | v1.0 |
| 6 | 品質仕上げ・リリース | E2E 全フロー、性能、アクセシビリティ、サンプルデータ、v1.0 | v1.0 |
| 7〜 | v1.x 拡張 | P2 機能（簡易税計算、目標、感度分析、繰上返済、PWA 等） | v1.x |

エンジン（Phase 1〜2）を UI より先に完成させ、計算の正しさをテストで固めてから画面を作る。各 Phase 終了時にユーザー承認を得てから次へ進む。

## 2. 各 Phase の作業と完了条件

### Phase 1: 基盤と計算エンジン中核

**作業**
1. Vite + React + TypeScript プロジェクト作成、ESLint（層分離の import 制約含む）・Prettier・Vitest 設定、`npm run lint / typecheck / test` 整備
2. `src/domain`: 型定義・Zod スキーマ（schemaVersion 1）
3. `src/engine/time`: 月番号・年齢・学齢・トリガー解決（date / age / school）
4. `src/engine/ledger`: 仕訳・一意キー検査・残高計算
5. 定常収支（頻度・期間・上昇率）、積立振替、運用（幾何月次換算）
6. ローン計算（元利均等・元金均等・金利変更）
7. 年次集計・指標、エンジン検証（calculation-spec §14）
8. `tools/verify/` Python 独立実装（G-01, G-02 相当まで）

**完了条件**
- [ ] `npm run lint`、`npm run typecheck`、`npm test` がすべて成功
- [ ] test-strategy §3 の単体テスト、§4 の境界値テスト（イベント以外）を実装し成功
- [ ] 不変条件（§9 の 1〜6）のプロパティテストが成功
- [ ] G-01, G-02 のゴールデンテストが独立実装と完全一致
- [ ] engine のカバレッジ 行 90% / 分岐 85% 以上
- [ ] engine が UI・ブラウザ API に依存しないことを lint で確認
- [ ] Phase 1 開始前が期限の open-questions（Q-01〜Q-07, Q-09, Q-10, Q-14, Q-18, Q-21）が決定済み

### Phase 2: 人生イベント展開

**作業**
1. イベント展開器レジストリ、決定的展開順序、`endsItemIds`、有効/無効
2. P1 イベント: 汎用一時収支、収支変更、就職/転職、退職、結婚、出産、教育費、賃貸、住宅購入、自動車、年金、老後生活費
3. 実物資産評価（年率変動）、資金不足検出・自動取り崩し
4. 教育費・子育て費などのテンプレート既定値（出典明記）
5. 独立実装を G-03〜G-05 まで拡張

**完了条件**
- [ ] test-strategy §5 の全項目（種別ごと）が成功
- [ ] G-01〜G-05 ゴールデンテストが完全一致
- [ ] プロパティテストにイベントを含めて成功
- [ ] Q-08, Q-11, Q-12, Q-13, Q-19 が決定済み

### Phase 3: 永続化とデータ管理

**作業**
1. IndexedDB 保存（デバウンス自動保存、退避世代、`storage.persist()`）
2. エクスポート（integrity 付き）、インポート（検証・プレビュー・退避・置換）
3. マイグレーション基盤（v1 のみでも枠組みとテストを用意）
4. 全データ削除

**完了条件**
- [ ] test-strategy §7 の全ケースが成功
- [ ] 往復（エクスポート→インポート）で計算結果が完全一致
- [ ] Q-15, Q-16 が決定済み

### Phase 4: UI（入力・結果表示）

**作業**
1. レイアウト・ナビゲーション・ヘッダ（シナリオ切替、前提チップ、保存状態）
2. ② プロフィール・前提、③ 収入・支出・資産、④ イベント（種別別フォーム）
3. ⑤ 資産推移（グラフ・年次表・明細ドロワー）、① ダッシュボード、⑧ 設定・前提、⑦ データ管理画面
4. 空状態、バリデーション表示、免責表示

**完了条件**
- [ ] ui-design.md の全画面が実装され、空状態・エラー表示が定義どおり
- [ ] E2E フロー 1・2・4・5 が成功
- [ ] グラフと年次表の値一致テストが成功
- [ ] 回帰: Phase 1〜3 の全テスト成功

### Phase 5: シナリオ比較

**作業**: シナリオ一覧・作成・複製（ID 振り直し）・削除、比較画面（重ね合わせグラフ・指標表・前提差異警告）

**完了条件**
- [ ] requirements.md の P1 機能がすべて実装済み（機能一覧に実装状況を記入）
- [ ] 全テスト（単体・ゴールデン・プロパティ・コンポーネント・E2E）成功
- [ ] 性能要件を測定で確認
- [ ] 既知の問題が一覧化され、v1.0 を阻害するものがない

## 3. Phase 完了時の報告フォーマット

各 Phase 終了時に以下を報告し、ユーザーの承認を得てから次 Phase に進む。

1. 変更ファイル一覧
2. 実装内容（実装済み / 未実装を明確に区別）
3. 実行したテストのコマンドと結果（件数・成功/失敗・カバレッジ）。実行していないテストは「未実行」と明記
4. 完了条件のチェック結果（未達項目があれば Phase を完了扱いにしない）
5. 既知の問題
6. 決定した仕様・新たに発生した未決事項
7. 次 Phase へ進むための条件
